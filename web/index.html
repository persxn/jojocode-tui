local or remote

Two ways to run the same agent

The client is identical either way — one curses app. What changes is where the loop runs and whose GPU answers.

local

Your machine, your model

The loop runs on your box and talks straight to Ollama on 127.0.0.1:11434. Nothing leaves the machine at runtime.

ollama-setup.sh installs the runtime; recommend-model.py reads your RAM / VRAM and pulls a model that fits.

remote

Someone else's GPU

jojo --remote https://host --login — email and a one-time code, then a WebSocket session.

The server runs the loop and the big model; tool calls still execute locally, path-jailed to your project, and you approve every destructive one. A dropped connection resumes without re-running a side effect.

the agent loop

It proposes; you decide; it verifies

The model can ask for a tool call — it cannot run anything. Destructive calls hit an approval wall regardless of any allow-list, and anything fed back to the model is framed as untrusted data.

Approval on every write.

y/n/a on each write_file and run_command, with a diff preview. Reads and listings are free.

Path-jailed.

Every path resolves inside the project root; ../, symlinks and absolute escapes are refused before the tool runs, not judged after.

Exactly-once tools.

Each tool_request carries a stable id and the client journals the result. Crash mid-call, reconnect, and the client answers from its journal without re-executing the side effect.

Knows when to stop.

The model says done · a per-turn tool cap · a wall-clock limit · your Ctrl-C · lost authorization. Then a one-paragraph summary.

research

When it isn't sure, it looks it up

Current versions, release dates, live APIs, an error nobody has seen before — the things a training cutoff cannot answer. web_search returns snippets; fetch_url reads the one or two that matter; the answer comes back summarised, with the URLs it rests on.

Cited, or marked unverified.

If the sources disagree it says so instead of picking one quietly. If the search found nothing, it answers from memory and tells you that is what it did.

Pages are data, never orders.

Fetched text arrives inside an UNTRUSTED WEB CONTENT envelope. A page that says "ignore your instructions" gets reported to you, not obeyed — and writes still need your y.

It can't read your network.

Every hostname is resolved before connecting, and loopback, RFC1918 and the cloud metadata address are refused — on the first request and on every redirect after it.

models

The biggest model the hardware can actually hold

recommend-model.py reads cores, RAM, NVIDIA VRAM and Apple or Grace-class unified memory, then ranks by a conservative usable-memory budget — a model that swaps is worse than a smaller one that doesn't.

install

One command, no root

Creates a private venv, installs the TUI, drops a jojo launcher on your PATH, and offers to set up Ollama. It installs Python itself if the machine has none.

Linux / macOS

Windows · PowerShell

security

The client's permission model is a security component

Not a convenience. The server proposes; the client decides. Everything that could change your machine stops at a prompt you have to answer, and that boundary is what makes the rest — remote models, fetched web pages — safe to have.
